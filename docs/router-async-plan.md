### Known problems in the current flagship sketch

The redesign must fix all of these:

1. **Glue code isn't eliminated.** The `ProjectEditor` example needs a manual effect, hand-made saving/error signals, try/catch, and a manual invalidate call. That's no better than React with TanStack Query.
2. **Reactivity bug:** `projectQuery.value(params())` reads route params once at setup, so navigating between projects with the same component mounted shows stale data.
3. **Query-to-form sync overwrites user edits** when data refetches.
4. **Route params are declared by hand** instead of inferred from the path string.
5. **No connection to the Benos UI components** (field-level errors in `Input`, etc.).
6. **No loading, error, or pending-navigation states**, and `ProjectEditor` misuses `createRoot`.

## 3. Goals for 0.4.0

### `@benosjs/async` (or the package name chosen in design)

- `resource()` per `async.md`: a discriminated state signal (`disabled | pending | ready | failed`), `initialValue`, refresh, cancellation via `AbortSignal`, generation checks against out-of-order responses, and disposal with the owner.
- `<Suspense>` and transitions per `async.md`, including the gating of effects and mounts in uncommitted branches.

### `@benosjs/router`

- **Typed routes with params inferred from the path string** (e.g. `'/projects/:projectId'` → `{ projectId: string }`), and typed search params with parsing.
- Nested routes and layouts, a not-found route, and redirects.
- **Route loaders** that start loading before the route renders, integrated with resources and Suspense, and **reactive to param changes** without remounting.
- `<Link>` with typed `to` and params (a wrong param name is a type error), active-link state, and `navigate()`.
- Pending navigation state, error boundaries per route, and lazy-loaded route components.
- History API integration (back/forward, scroll restoration) and a memory history for tests.
- Accessibility: focus management and announcing route changes for screen readers.
- Works in RTL and with the Benos UI components.

### Not in this track (0.5.0)

Query cache, mutations, forms, the full flagship integration, and blocks (`benos add login`). But **the router's API must be designed so the redesigned flagship works on top of it without router changes.**
