# S2 — Server renderer

**Status:** Awaiting approval. S1 was approved on 2026-10-28 with all twelve decisions. The user's words: "Approve S1 with all 12 decisions, including the query cap of 3,840 B. Start S2: the server renderer. Stop at the s-s2 checkpoint."

## Delivered

- **`@benosjs/server`** (new package, [`packages/server`](../../packages/server)): `renderToString(app, options)` as [ssr.md](../architecture/ssr.md) specifies. [`nodes.ts`](../../packages/server/src/nodes.ts) is the request-local tree (linked lists, no DOM identity). [`host.ts`](../../packages/server/src/host.ts) is the server host over the same descriptors and template plans the DOM renderer consumes: values, elements, templates, components, `Show`, `For`, `Switch`/`Match`, `Dynamic`, `Portal` (pair only), `ErrorBoundary`, context providers, and registered internal controls through the `host` argument. [`serialize.ts`](../../packages/server/src/serialize.ts) escapes by context, handles void, RCDATA, raw-text, and `noscript` elements, writes a textarea's value as its content, and runs the development structure checks. [`render.ts`](../../packages/server/src/render.ts) creates the request root at gate 1, settles in rounds, serializes, builds and bounds the payload, and disposes in `finally`.
- **Core seams** ([`runtime.ts`](../../packages/core/src/runtime.ts)): per-parent creation ordinals (`ordinal`, `childOrdinal`; run owners inherit their effect's ordinal; slots claim an ordinal and every branch reuses it), the root `request` record through `internalRequest()`, `createUniqueId` deriving `b<root>-<path>-<n>` under a request, `createInternalOwner(kind, mountReady, key, ordinal)`, `claimInternalOrdinal()`, and the two development warnings. The gated-set cleanup at disposal already existed.
- **DOM seams** ([`index.ts`](../../packages/dom/src/index.ts)): internal controls receive a `host` (`comment`, `insert`, `remove`, `stage`); slots carry their ordinal; keyed `For` items get `k<encoded key>` as their id segment; comment creation and removal go through the host object (a byte saving that also makes the hydrate entry's job smaller).
- **Async** ([`index.ts`](../../packages/async/src/index.ts)): `Suspense` mounts through `host`; `resource` under a server root never launches without a codec (permanent pending token; a read outside Suspense throws), launches and tracks with a codec, records `[id, key, serialize(value)]` on success, and stays pending with `onError` on failure; under a hydrating root it seeds from a matching snapshot and consumes it. The hydrating half is here because it is the same code path; S3 exercises it through `hydrate`.
- **Runtimes and CI:** [`scripts/test-server-runtime.mjs`](../../scripts/test-server-runtime.mjs) renders a fixture with the built packages and checks the output imports no `node:` module; `pnpm test:server-runtime` runs it on Node in `verify`, and the new `server-bun` job runs it on Bun. Both pass locally (Node 26.10, Bun 1.3.2).
- **Wiring:** build, root tsconfig, `check:packed` (13 packages), and `pnpm size` (server cap 6,144 B) know the package. `@benosjs/server` is at 0.5.1 like the others; S6 bumps it with the release.
- **Docs:** [ssr.md](../architecture/ssr.md) records two details measured in S2: an empty value inside a pair keeps its empty comment (`<!--b--><!----><!--/b-->`), and Suspense and RouterOutlet leave their own empty comment after their content, as on the client.

## Decisions taken in S2 (within S1's approvals)

1. Render-tier bindings subscribe during the request (S1 decision 1); the settle loop yields one microtask per round so Suspense can reveal, then awaits every tracked promise, until nothing is tracked or the signal aborts.
2. A registered internal control (Suspense, RouterOutlet) is reached through the `__benosDomControls` registry `@benosjs/dom` already keeps; no new registry.
3. `createUniqueId` shares the owner's child counter with child owners and slots instead of a separate counter, which saved bytes and keeps determinism (every call happens in setup order on both sides).
4. The id segment for a keyed item is `k` + `encodeURIComponent(key)`; it is always a valid `id` and needs no regex.
5. Internal API guards (`claimInternalOrdinal` without an owner, `internalRequest` outside `createRoot`) were dropped for bytes; the callers are in-repo.
