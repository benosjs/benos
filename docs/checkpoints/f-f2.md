## Finding: A → B → A brought back discarded edits

The design used the `match.data()` handle as the identity. Query's `load()` returns **one handle per entry**, so after A → B → A the router publishes A's original handle again, and edits tagged with it would reappear after the user had left the record. The epoch is now a fresh token whenever the identity differs from the previous one. The regression test `does not bring back earlier edits after A → B → A` pins it.

## Open points

- **`form.field()` inside a `computed` throws,** because it creates signals. That is the kernel's rule, not a forms rule, but the guide must say to request fields during setup. `<form.Field>` does.
- **Per-keystroke cost.** Editing one field reruns only that field's bindings (pinned by a test). `values()` and `form.dirty()` scan the fields that have been edited.
