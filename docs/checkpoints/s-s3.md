## The cap decision

| Bundle                  | Before S3 | After S3   | Cap    | Over by |
| ----------------------- | --------- | ---------- | ------ | ------- |
| `@benosjs/core` + `dom` | 11,258    | **11,508** | 11,264 | 244 B   |
| `@benosjs/dom/hydrate`  | —         | **3,044**  | 2,048  | 996 B   |
| `@benosjs/core`         | 4,478     | 4,478      | 4,608  | —       |
| `@benosjs/async`        | 1,873     | 1,886      | 4,096  | —       |
| `@benosjs/server`       | 5,318     | 5,379      | 6,144  | —       |

The claim cursor in `@benosjs/dom`'s main entry costs **250 B** (210 B for the creation-site hooks, 32 B for `hold()`, 8 B for the claimed-element write check). S1 estimated 190–260 B. It is the approved seam, implemented as nine small sites that each ask one hook (`claim?.(kind, parent, before, arg) ?? create`), and there is no cheaper shape I could find: moving the hooks behind a single `insert()` interception does not work because the renderer holds references to the nodes it creates, and a document proxy breaks on template prototypes. `pnpm size` fails on the branch until this is decided.

- **Proposal for the pair: raise the cap to 11,520 B** (+256, the figure flagged at S2). That leaves 12 B; S4 and S5 change query, router, forms, and Vite, not core or DOM.
- **Proposal for `@benosjs/dom/hydrate`: set the cap to 3,328 B.** The S1 figure of 2,048 was a guess before the walker existed. The entry holds the payload reader, the cursor, keyed-item transparency, stage pairing, the plan and direct-template walkers, mismatch reporting, and recovery; the development messages are stripped in production. Client-only apps never load it.

## Delivered

- **`@benosjs/dom/hydrate`** ([`hydrate.ts`](../../packages/dom/src/hydrate.ts)): `hydrate(app, host, options)` as [ssr.md](../architecture/ssr.md) specifies. It finds the root markers (version checked), reads and validates the payload script, creates the hydrating root with the request record and gate 1, installs the claim hook, mounts the app with the DOM renderer, then removes leftovers and markers, opens the gate, and runs mounts. The claimer keys its cursor by the insertion point (`before`, or the parent when appending), so slot contents that mount later from render effects claim from their own pair; keyed-item wrappers are transparent; a stage pair is claimed only by the stage with the matching ordinal; mismatches recover by client rendering the rest of the key's range and are reported once.
- **DOM seams** ([`index.ts`](../../packages/dom/src/index.ts)): the claim hook at text, comment, slot-marker, element, template, direct-template, and stage creation; `insert` leaves a claimed node in place; attribute and property bindings skip their first write on a claimed element; `prepareInternalStage` can mount in place and `hold()` the result; the `__benosDomHydrate` registry.
- **Server markers** ([`host.ts`](../../packages/server/src/host.ts)): `For` items are wrapped as `<!--i-->` … `<!--/i-->` and a committed stage as `<!--b:N-->` … `<!--/b-->`, so the client can tell item wrappers, slot pairs, and stage pairs apart. [ssr.md](../architecture/ssr.md)'s grammar table and hydration section record this.
- **Async** ([`index.ts`](../../packages/async/src/index.ts)): Suspense passes `before` to `host.comment` and, when its first reveal finds pending tokens, holds content that was claimed in place, so a missing or mismatched payload shows the fallback alone.
- **Wiring:** the `hydrate` entry in the DOM build and `exports`, a size entry, and the browser harness aliases for `@benosjs/dom/hydrate` and `@benosjs/server`.

## Found and fixed while building

1. A fresh node created during hydration (portal content, a recovered range) got no attributes, because the first-write skip applied to every element while the cursor was active. It now asks the claimer whether the element was claimed.
2. `insert` skipped fragment children (they have a parent) and so dropped a fresh Suspense fallback. It now skips only a node already under the target parent.
3. Content claimed in place must be held when its first reveal finds pending tokens; deciding at stage time is too early, because bindings read their resources in the deferred render flush.
4. The compiler's direct-template paths are relative to the root element, not the prototype fragment; the claimer resolves them that way.
5. A `.tsx` fixture that calls the `jsx` runtime is rejected by the compiler as already-lowered JSX; the fixture is a `.ts` file.
