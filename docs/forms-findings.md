# Forms findings from a TanStack Form and React Hook Form user's perspective

Two apps now edit server data with `@benosjs/forms`: the dashboard's project editor (name and owner, a Valibot schema, server issues, and the leave policy) and the flagship editor in [`examples/flagship`](../examples/flagship), which is the [flagship target](./architecture/flagship-integration.md) as executable code next to the same editor in React with TanStack Router, Query, and Form. These notes record where the workflow differs from React with TanStack Form or React Hook Form. Each item is a `0.5 fix` (done in this track), a `0.5 item` (needs a decision before 0.5.0), a `later` item, or an `accepted trade-off`.

| Finding                                                      | What felt different or confusing                                                                                                                                                                                                                                                                                                                                                                          | Status                                                                                                                                            |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| No `key` and no wrapper component                            | In React, the record comes from `useSuspenseQuery` in a page component, which passes it to a keyed editor so `useForm` sees new `defaultValues` on a record change. The Benos editor calls `projectForm()` and nothing else: the form follows the committed route data, resets at the commit of another record, and keeps the same component. A React developer looks for the `key` and does not find it. | `accepted trade-off` — this is the design; the guide must say where identity comes from.                                                          |
| Refetches and dirty fields                                   | TanStack Form follows changed `defaultValues` only while the form is untouched, and React Hook Form needs `values` with `resetOptions: { keepDirtyValues: true }`. Benos updates every pristine field on a refetch and keeps each dirty one, per field, with `remoteChanged()` for conflicts. The dashboard shows a "changed on the server" notice with one `acceptRemote()` button.                      | `accepted trade-off` — the per-field rule is the default and cannot be turned off.                                                                |
| Leaving with unsaved changes is on by default                | The React editors need `useBlocker({ shouldBlockFn, enableBeforeUnload })` and a dirty check. The Benos form asks by default, including on Back and on unload. In tests this surprised me: happy-dom has no `window.confirm`, a missing `confirm` counts as a refusal, and a navigation from a dirty form silently returned `{ status: 'blocked' }`.                                                      | `accepted trade-off` — documented in [forms.md](./architecture/forms.md#f5-implementation-notes); tests stub `confirm` or use `leave: 'discard'`. |
| Leaving after a save                                         | TanStack Form's `isDirty` stays true after a save, so the React editors call `formApi.reset(value)` after `mutateAsync` and block on `!isDefaultValue`; without the reset, leaving after a save asks. The Benos post-save rebase clears the submitted fields, so the form is pristine.                                                                                                                    | `accepted trade-off` — less code; nothing to configure.                                                                                           |
| The blocker cannot tell a same-record navigation             | A hash link or a search change on the same project still asks while the form is dirty, because the blocker sees only the destination URL. React's `useBlocker` has the same limit unless `shouldBlockFn` compares locations by hand.                                                                                                                                                                      | `later` — would need the router to match the destination before asking.                                                                           |
| No "saved" state                                             | TanStack Form has `isSubmitSuccessful` and React Hook Form has `formState.isSubmitSuccessful`. The Benos form has `submitting()` and `error()`, but no success flag, so the dashboard keeps a `saved` signal set from `submit()`'s result to show "Saved.".                                                                                                                                               | `later` — a `form.saved()` accessor is a candidate; it costs bytes in a package with 194 B of headroom.                                           |
| Server issues map to fields                                  | A 422 whose error carries Standard Schema `issues` shows "Another project already uses this name." under the name field, linked by `aria-describedby`, with no code in the editor. React Hook Form needs `setError` per field, and TanStack Form needs `onSubmitAsync` to return field errors.                                                                                                            | `0.5 fix` — implemented in F3; the dashboard now uses it.                                                                                         |
| `<form.Field component={Input}>` instead of a render prop    | Two fields are two lines in Benos, against 15 to 26 lines each in the React editors, because `<form.Field>` renders the label, error, ids, and `aria-describedby`. A custom layout uses the headless `form.field()` instead. A component that does not accept the controlled props fails with "not assignable to `never`" on `component`, which does not say why.                                         | `accepted trade-off` for the markup; the error message is a `later` item (F4 note 5).                                                             |
| `from` sees whatever the loader returned                     | The dashboard's `getProject` resolves `null` for an unknown id, so `from` had to handle `null` (`project?.name ?? ''`), even though the editor renders only when the project exists. In React the editor receives a non-null `project` prop.                                                                                                                                                              | `later` — the loader could throw a not-found instead, or `from` could return `undefined` for "no record".                                         |
| `async` submit handlers warn                                 | `onSubmit={async (event) => { … await form.submit(event) … }}`, which React developers write constantly, made the Benos compiler warn "await and yield are not supported in JSX bindings". The dashboard now uses `form.submit(event).then(…)`. An event handler is not a binding, so the warning is a false positive here.                                                                               | `later` — the compiler should not warn for `on*` handler functions.                                                                               |
| Registry inputs do not reflect errors after the first render | After a failed submit, the error text is linked, but the registry `Input` keeps `aria-invalid="false"` and its normal border. React components re-render with the new prop.                                                                                                                                                                                                                               | `0.5 item` — fixed in F6 with the 0.5.0 registry build, as approved at F4.                                                                        |
| Module-level definitions in tests                            | `query`, `mutation`, and `formModel` are module singletons that use the default cache, so the flagship tests reload the modules for each test (`vi.resetModules()`) to start with an empty cache. React tests create a `QueryClient` per test.                                                                                                                                                            | `later` — a documented test recipe, or a cache option for `createRouter` that loaders inherit.                                                    |
| Forms without the router still load it                       | `@benosjs/forms` imports the router's `blockNavigation`. An app using forms without the router pays about 944 B (about 400 B router, about 544 B of `@benosjs/async` module setup). TanStack Form and React Hook Form are router-agnostic.                                                                                                                                                                | `0.5 item` — decision in the [F5 checkpoint](./checkpoints/f-f5.md).                                                                              |

## What the measurements show

The flagship slice is 13 lines of editor and 49 lines in all for Benos, against 81 and 104 for React with native inputs and 100 and 123 with shadcn/ui fields, with the same behavior: typed params, loader-primed cache, identity reset, refetch handling, Standard Schema validation, accessible field errors, success invalidation, and a leave policy. The production bundle of the slice is 24,923 B gzipped for Benos and 124,879 B for React, both without Zod (Zod adds about 23 KB to each).

What the numbers do not show: the React editors are written the way the TanStack and shadcn guides write them, and a React team would extract a `TextField` component after the second field, which removes most of the per-field lines; the Benos count would not change, because `<form.Field>` is that component. The bundle numbers compare whole stacks, most of which is React DOM and TanStack Router, not the forms libraries; the forms packages themselves are 2,878 B for Benos against 17,483 B for `@tanstack/react-form` and 13,313 B for `react-hook-form` (measured at F1). Neither number is a runtime benchmark.

The original sketch's React route used `createFileRoute`, which does not compile without TanStack Router's route generator. The executable version uses code-based routes, which needed a root route and a router in the counted setup; the Benos setup always counted its router.

## Validation

The flagship tests render the compiled editor against an in-memory API in happy-dom: commit-time identity, background results, refetches, a save finishing after navigation, Zod, Valibot, ArkType, async validation, root issues, save failures that never reach the event reporter, and the leave policy. Its type tests pin the four reserved type errors. `pnpm check:flagship` type-checks both stacks and fails if [flagship-integration.md](./architecture/flagship-integration.md) shows different code or counts. The dashboard's browser tests cover saving, client and server validation with focus, and leaving with unsaved changes by link and by Back, in Chromium, Firefox, and WebKit.
