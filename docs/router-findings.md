# Router findings from a React developer's perspective

This dashboard uses the public router and component APIs. These notes record
where the workflow differs from a React application and classify each item as
a `0.4 fix`, a `0.5 item`, or an `accepted trade-off`.

| Finding                                                 | What felt different or confusing                                                                                                                                                                                                         | Disposition                                                                                                                                                                                                                                     |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components run once                                     | A component function sets up its owner once; it does not rerun after each state change as a React function component does. Signal reads in JSX stay reactive.                                                                            | `0.4 fix` — foreground the run-once model in the React migration guide and examples.                                                                                                                                                            |
| Props use accessors                                     | Reactive props are getter-backed. Destructuring a prop into a local value can capture a stale value, unlike React's render-time snapshots.                                                                                               | `0.4 fix` — keep the props lint rule and show `splitProps` or getter reads in migration examples.                                                                                                                                               |
| Route references and route views live in separate files | `route()` references are declared separately from the `mountRoute()` manifest so page imports do not create circular module evaluation. This adds indirection compared with a colocated route component.                                 | `accepted trade-off` — it keeps lazy page imports and typed links independent of page module loading.                                                                                                                                           |
| Route state is only available in its matching owner     | `projectRoute.match()` must run while its route view is being set up. The returned params and data are accessors; reading them once in setup gives a snapshot.                                                                           | `0.4 fix` — add a short recipe to the router guide showing accessor reads inside JSX and effects.                                                                                                                                               |
| `<For>` passes accessors                                | A keyed list callback receives `project()` rather than a plain row value. This preserves item identity during list updates, but is unfamiliar to React developers.                                                                       | `0.4 fix` — include an explicit React-to-Benos example in the migration guide.                                                                                                                                                                  |
| Nested route manifests are explicit                     | Layouts and index routes are nested with `mountRoute` and rendered through `Outlet`; this makes ownership and route boundaries visible but takes more setup than a flat route-object convention.                                         | `0.4 fix` — add a complete list/detail manifest example to the getting-started router guide.                                                                                                                                                    |
| Loader caching is not included                          | A loader runs for a new navigation and the router does not deduplicate or cache data across visits.                                                                                                                                      | `0.5 item` — addressed in the query track (Q4): loaders that use `query.load` reuse cached entries on revisits, and mutations refresh committed route data. See [query.md](./architecture/query.md#router-loaders-share-identity-with-queries). |
| Route errors and render errors use separate boundaries  | Loader and lazy-import failures belong to a route's `error` view; component render errors go to the DOM `ErrorBoundary`. This split is predictable once learned, but not obvious at first.                                               | `0.4 fix` — document the boundary order and show retry behavior.                                                                                                                                                                                |
| Nested detail route outlet transition                   | A page whose root is control flow (here `<Show>`) captured the staging fragment as its parent. After the router committed the stage, a later branch change inserted into that detached fragment and threw `insertBefore` in the browser. | Fixed in 0.4 — the DOM renderer now resolves an anchor's live parent and re-anchors slot markers before disposal. The detail route is nested under the projects layout with regression tests in DOM, router, and the dashboard browser suite.   |
| JSX uses `class` and `for`                              | The compiler intentionally diagnoses `className` and `htmlFor`; React muscle memory can produce those names.                                                                                                                             | `accepted trade-off` — use the standard DOM names supported by Benos and keep the diagnostic explicit.                                                                                                                                          |
| Links retain browser semantics                          | The router's `Link` renders an anchor and intercepts only eligible same-origin clicks. Modified clicks, target, and download links keep native browser behavior.                                                                         | `accepted trade-off` — this keeps keyboard, context-menu, and open-in-new-tab behavior familiar.                                                                                                                                                |

## Dashboard validation

The dashboard is type-checked and built in CI. Its browser tests exercise the
overview, loader-backed project list and detail navigation, browser back, and
the not-found view in Chromium, Firefox, and WebKit.
