### Constraints carried over from 0.4 and the query track

1. **No stale identity.** A form never shows record A's edits, errors, or submission state under record B's identity, and never resets before the router commits B.
2. **Synchronous graph.** Signal writes stay synchronous; async validation and save completion are ordinary batched writes guarded by generations.
3. **Owner lifetime.** Form instances, field handles, and navigation blockers belong to the component owner. A save that finishes after disposal still applies its cache effects (query rule) but writes no form state.
4. **No hidden behavior.** Every default (validation timing, leave policy, mutation input shape) is explicit and documented. No global listeners except while a dirty form asks the router to block.
5. **Events never throw.** `form.submit` never rejects and never reaches the DOM event error reporter.

## 3. Goals for the forms track

### `@benosjs/forms`

- `formModel()` definitions bound to a route, a tracked source, or static initial values; owner-bound form instances.
- Identity rules: reset on a committed identity change, pristine fields follow same-identity refetches, dirty fields are never overwritten, and `remoteChanged` reports conflicts.
- Standard Schema v1 validation, sync and async, with issue-path mapping to fields and root issues to the form.
- Submission through a query mutation with typed input binding, double-submit protection, and error capture.
- `<form.Field>` and headless `form.field()` with accessible label, description, and error wiring for the registry `Input`, and adapters for checkbox, switch, select, and radio-group controls.
- An explicit leave policy for unsaved changes, using a router navigation blocker if approved.

### Not in this track

Field arrays with insert/remove/move helpers, per-field validator functions outside the schema, multi-step wizards, file uploads, SSR of forms, server actions, devtools, and a schema-introspecting form generator.
